# PRD 提纲模板

> 本模板用于 PHASE 1。
>
> 产品需求 Agent 应基于当前对话、Project / Workspace 上下文、用户指定资料和已确认上游 Artifact 生成提纲。
>
> 目标不是提前写完整 PRD，而是让用户一次性确认：整体结构、需求范围、实验、埋点、增强项和所有关键不确定项。

# PRD 提纲：[需求名称]

## 一、需求背景

### 1.1 背景与现状

用 2–5 句概括：

- 当前业务 / 产品现状；
- 当前出现的问题；
- 为什么产生本次需求。

### 1.2 当前问题

列出本次需求准备解决的核心问题。

### 1.3 用户故事

仅列出必要的用户故事，用于帮助理解“谁需要什么，以及为什么需要”。

格式：

- 用户1：作为 [用户角色]，我希望 [完成某项目标或操作]，以便 [获得某种价值]。
- 用户2：……

---

## 二、需求价值
说明本次需求要达到什么目标。

### 2.1 定性价值

可包括：

- 用户价值；
- 业务价值；
- 效率价值；
- 体验价值。

仅列与当前需求实际相关的内容。

### 2.2 定量价值

如果已有可靠数据：

- Baseline：
- 目标指标：
- 目标值：

如果没有可靠数据：

> 当前资料未提供明确量化目标，正式 PRD 中不自行补充。

---

## 三、需求范围

输出初步范围表：

| 页面 | 功能模块 | 功能点概述 | 涉及团队 |
|---|---|---|---|
| [页面] | [模块] | [功能点概述] | [团队] |

规则：

- 这里只列本期真实范围；
- 已明确不在本期范围内的内容应说明；
- 若范围存在冲突，在末尾“待确认事项”中统一暴露。

---

- 交互方案来源：

#### 4.1.2 [功能模块 / 功能点]

- 计划描述：
- 交互方案来源：
- 是否存在已确认业务规则：

（更多页面 / 模块按实际情况展开）

---

## 交互方案状态

明确说明当前属于哪一种情况：

### A. 已有交互方案

> 已发现并将直接引用：[交互 Artifact 名称 / 版本]。产品需求 Agent 不重复设计。

### B. 不涉及交互改动

> 本需求不涉及新增或修改 UI / 交互，不生成交互设计内容。

### C. 涉及交互改动，但缺少交互方案

> 当前项目涉及交互改动，但尚未发现可用的交互方案。应先由交互 Agent 产出并确认交互方案，再继续完整 PRD 生成。

---

## 需求详情增强项

请用户一次性确认正式 PRD 是否需要以下增强项：

- 状态说明（加载 / 成功 / 失败 / 空状态）：是 / 否 / 待确认
- 异常与边界：是 / 否 / 待确认
- GIVEN / WHEN / THEN 验收标准：是 / 否 / 待确认

支持用户：

- 全部需要；
- 仅选择部分；
- 都不需要。

---

## 五、AB实验

### 是否有 AB 实验需求

> 是 / 否 / 待确认

如果“是”，提纲中展示已有信息：

- 实验目标：
- 核心指标：1 个
- 观测指标：多个
- 实验分组：
  - 空白对照组；
  - 对照组；
  - 实验组1；
  - 实验组2；
  - 实验组3（如有）
- 实验周期：如资料中已有则填写，否则标记待确认

如果“否”：

不生成AB实验章节。

如果“待确认”：

> 在下方待确认事项中说明原因并给出建议。

---

## 六、埋点

### 是否有埋点需求

> 是 / 否 / 待确认

如果“是”，提纲中先列计划覆盖范围即可：

- [页面] / [功能模块] / 曝光；
- [页面] / [功能模块] / 点击；
- ……

正式 PRD 再以标准表格输出。

如果“否”：

不生成埋点章节。

如果“待确认”：

> 在下方待确认事项中说明原因并给出建议。

---

## 待确认事项

> 仅在存在真实不确定项、冲突或缺失信息时输出。

格式：

| 序号 | 优先级 | 章节 | 待确认事项 | 建议 |
|---|---|---|---|---|
| 1 | P0/P1/P2 | [章节编号 + 名称] | [问题] | [建议] |

优先级：

- P0：阻塞需求开发、范围确定或核心方案落地；
- P1：不一定阻塞开发启动，但影响功能完整性、实验、数据或重要交互；
- P2：低风险细节，可后续确认。

---

## 固定确认提示

在提纲末尾固定输出：

> 请确认以上 PRD 提纲及待确认事项。
> 同时请确认“状态说明 / 异常与边界 / GIVEN-WHEN-THEN 验收标准”是否需要。
> 确认后我再生成完整 PRD 草稿。

**在用户确认前，禁止进入 PHASE 2。**
