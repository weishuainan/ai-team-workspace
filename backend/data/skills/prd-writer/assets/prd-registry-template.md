# PRD Registry 模板与管理规范

> 本文件用于 PHASE 3。
>
> Registry 的目标是：
>
> - 每个 PRD 一行；
> - 每个需求有固定 PRD ID；
> - Registry 永远指向最新 PRD；
> - 历史版本不在 Registry 中重复保留；
> - 历史版本由文档版本体系或版本控制系统追溯。

# 1. 推荐文件路径

```text
docs/PRD_REGISTRY.md
```

单个 PRD 推荐路径：

```text
docs/prd/PRD-001.md
docs/prd/PRD-002.md
...
```

如项目已有自己的目录规范，以项目规范为准。

---

# 2. PRD ID

格式：

```text
PRD-001
PRD-002
PRD-003
...
```

规则：

1. PRD ID 表示“这是哪一个需求”；
2. 同一个需求后续迭代时，PRD ID 保持不变；
3. 新需求才创建新的 PRD ID；
4. PRD ID 不等于文档版本。

---

# 3. Document Version

单个 PRD 文档内部维护版本，例如：

```text
v1.0
v1.1
v2.0
```

建议语义：

- v1.0：首次正式确认版本；
- v1.1：小范围补充、文案调整、规则修订；
- v2.0：需求范围或核心方案发生较大调整。

PRD ID 与 Document Version 必须分开：

```text
PRD-001 = 需求身份
v1.1    = 当前文档版本
```

---

# 4. Registry 标准格式

```markdown
# PRD 总集

| PRD ID | 标题 | 需求内容摘要 | PRD 链接 |
|---|---|---|---|
| PRD-001 | [需求标题] | [摘要] | docs/prd/PRD-001.md |
```

---

# 5. 字段说明

## PRD ID

固定需求标识。

## 标题

PRD 当前正式标题。

## 需求内容摘要

使用自然语言写清：

- 需求目标；
- 主要范围；
- 核心功能；
- 关键规则；
- 重要边界；
- 如适用，可简要说明 AB 实验或埋点；
- 明确非目标（如有）。

建议 3–8 句。

不得使用大量内部缩写堆砌。

## PRD 链接

永远指向该需求当前最新 PRD。

---

# 6. 新建 PRD

新建需求时：

1. 获取当前 Registry 中最大的 PRD ID；
2. 分配下一个 ID；
3. 保存 PRD 文件；
4. 在 Registry 追加一行；
5. 文档内部版本通常从 v1.0 开始。

示例：

```markdown
| PRD-004 | 新用户任务体系 | 目标是降低新用户首次使用门槛，并通过任务入口和任务列表帮助用户完成关键动作。范围包括首页入口、任务列表及任务状态展示。核心规则以已确认方案为准。若存在 AB 实验，则在 PRD 中记录实验分组与指标；埋点覆盖核心曝光与点击路径。 | docs/prd/PRD-004.md |
```

---

# 7. 更新已有 PRD

如果用户修改的是已有需求：

1. 不创建新的 PRD ID；
2. 更新原 PRD 文件；
3. 更新文档内部版本；
4. 更新 Registry 中该 PRD 对应的一行；
5. Registry 仍只保留一行，不保留旧版本记录。

例如：

```text
PRD-004
v1.0 → v1.1
```

Registry 仍然是：

```markdown
| PRD-004 | 新用户任务体系 | [更新后的摘要] | docs/prd/PRD-004.md |
```

---

# 8. Registry 不负责的事情

Registry 不负责：

- 保存完整历史版本；
- 保存每次修改记录；
- 保存 人工审核 过程；
- 保存所有旧 PRD 文件链接；
- 记录每次小改动的 diff。

这些应由文档版本记录或版本控制系统处理。

---

# 9. PHASE 3 完成条件

只有满足以下条件，PHASE 3 才算完成：

1. 用户已经明确确认 PHASE 2 的 PRD 草稿；
2. 正式 PRD 文件已保存；
3. PRD ID 已确定；
4. Document Version 已写入 PRD；
5. Registry 已新增或更新对应行；
6. Registry 中的链接指向当前最新 PRD。
