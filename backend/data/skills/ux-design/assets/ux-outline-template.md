# 交互方案提纲模板

> 本模板用于 PHASE 1。
>
> 目标不是提前产出完整交互方案，而是让用户一次性确认：设计目标、设计范围、主流程、主要页面 / 区域、交互复杂度和最终交付形式。

# 交互方案提纲：[需求名称]

## 一、设计目标

用 1–3 句话说明：

- 谁使用；
- 要完成什么；
- 本次交互设计希望解决什么问题。

---

## 二、设计范围

| 页面 / 区域 | 功能模块 | 本次设计内容 |
|---|---|---|
| [页面 / 区域] | [模块] | [交互设计内容] |

规则：

- 只列本期真实范围；
- 不擅自新增页面或模块；
- 如上游明确非本期范围，可简要说明。

---

## 三、用户主操作流程

用简短步骤说明：

```text
[入口]
→ [操作1]
→ [反馈 / 页面]
→ [操作2]
→ [结果]
```

只表达上游已确认的主路径和已确认分支。

不要自行补充异常 / 失败 / 降级流程。

---

## 五、交互复杂度判断

### 判断结果

> 简单 / 复杂

### 判断理由

说明 1–3 个最关键理由。

### 推荐交付形式

#### 简单需求

选择最合适的一种：

- 简要文字说明 + ASCII 线框图；
- 简要文字说明 + Mermaid 流程图；
- 简要文字说明 + ASCII + Mermaid 流程图（确有必要时）。

#### 复杂需求

> 简要文字说明 + HTML 交互原型

如需要额外辅助图，说明：

- ASCII Wireframe：需要 / 不需要
- Mermaid Flowchart：需要 / 不需要
- Mermaid State Diagram：需要 / 不需要
- Mermaid Sequence Diagram：需要 / 不需要

其中 State / Sequence 非必要不展示。

---

## 六、设计依据

简要列出主要上游来源：

- [Artifact / 文档 / 对话]
- [Artifact / 文档 / 对话]

只列关键来源，不需要做完整资料清单。

---

## 七、待确认事项

仅在存在真实冲突、缺失或未决问题时输出。

| 序号 | 影响区域 | 待确认事项 | 建议 |
|---|---|---|---|
| 1 | [页面 / 流程] | [问题] | [建议] |

不要为了“完整”主动新增异常 / 失败类待确认项。

---

## 固定确认提示

在提纲末尾固定输出：

> 请确认以上交互方案提纲、设计范围和推荐交付形式。
> 确认后我再生成完整交互方案。

**在用户确认前，禁止进入 PHASE 2。**
