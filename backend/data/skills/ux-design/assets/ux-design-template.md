## 路径 A：简单需求

### A1. ASCII Wireframe

当“页面长什么样”更重要时使用。

```text
+------------------------------------------------------+
| [页面标题]                            [操作]          |
+------------------------------------------------------+
| [导航 / 筛选 / 工具区]                               |
+------------------------------------------------------+
|                                                      |
| [主要内容区域]                                       |
|                                                      |
+------------------------------------------------------+
```

要求：

- 重点表达布局、层级和模块关系；
- 不追求视觉精度；
- 不为了“完整”加入上游未定义模块；
- 可用注释说明点击后去向。

### A2. Mermaid Flowchart

当“用户怎么走”更重要时使用。

```mermaid
flowchart TD
  A[进入功能] --> B[用户操作]
  B --> C[页面 / 系统反馈]
  C --> D[下一步操作]
  D --> E[完成]
```

要求：

- 只画已确认主流程；
- 只画已确认分支；
- 不自行补异常 / 失败 / 降级路径。

### A3. 两者同时使用

只有当页面布局和流程都对理解方案很重要时同时使用。

## 路径 B：复杂需求

### B1. HTML 交互原型

正式产物：

> [prototype.html 路径 / 链接]

# 四、状态与时序图（条件章节）

> 仅在确有必要时生成。
>
> 若不需要，整章不生成。

## 4.1 Mermaid State Diagram

仅使用上游已明确状态。

```mermaid
stateDiagram-v2
  [*] --> 状态A
  状态A --> 状态B: 已确认触发条件
  状态B --> 状态C: 已确认触发条件
```

不得自行增加异常 / 失败状态。

## 4.2 Mermaid Sequence Diagram

仅在多主体先后关系影响用户体验时生成。

```mermaid
sequenceDiagram
  participant U as 用户
  participant A as Agent
  U->>A: 已确认用户操作
  A-->>U: 已确认用户可见反馈
```

不写底层 API / HTTP / 技术实现。
