# 用户问题分析 — 测试 Case

## Case 1：用户反馈型场景 — 外卖新用户首单转化优化

**前置条件**：Skill 02 的 Case 1 已执行并通过确认。

**输入**：

```
项目名称：外卖新用户首单转化优化
项目目标：找到新用户首单流失的核心节点，并形成可进入需求评审的优化方案

已确认材料总结（摘要）：
- 核心事实：首单转化率从42%降至35%（来源：卫帅楠，置信度：高）；收到12条用户反馈（来源：张思琪，置信度：高）；下单耗时从3分钟变为5分钟（来源：卫帅楠，置信度：低）；App Store 有用户评论吐槽（来源：张思琪，source_type: user_feedback）
- 用户问题：优惠券找不到入口（高频）；不知道怎么下单更便宜（中频）
- 冲突点：高文颖主张首页放红包入口 vs 卫帅楠担忧影响老用户信息流体验
- 观点：卫帅楠认为先搞清楚原因再定方案

当前指令：根据材料总结和讨论，分析新用户首单流失的核心问题及原因
```

**期望输出要点**：

- `user_profiles`：外卖新用户（首次使用外卖App点餐的C端用户，对优惠券和下单流程不熟悉，价格敏感）
- `scenarios`：首单下单场景（触发：首次打开外卖App → 期望：快速便宜地下第一单 → 实际：下单耗时5分钟以上，领了优惠券但在结账页找不到入口）
- `pain_points`：
  - 下单流程过长导致结账环节流失（影响：高，频率：频繁，evidence引用"下单3→5分钟"和"12条反馈""App Store差评"）
  - 优惠券在结账页找不到使用入口（影响：高，频率：频繁）
  - 不知道怎么下单更便宜（影响：中，频率：偶尔）
- `known_facts`：至少3条，引用材料总结中的核心事实
- `cause_hypotheses`：
  - H1 [judgment]：选餐流程改版导致下单步骤增加，用户耐心耗尽中途流失（支撑事实：下单耗时变化、转化率下降、反馈数量；置信度：medium；验证方式：对比新旧版本各步骤流失率，拉取下单漏斗数据）
  - H2 [judgment]：优惠券展示入口在结账页不够显眼，用户已领取但未使用（支撑事实：12条反馈中"优惠券找不到入口"；置信度：medium；验证方式：分析结账页优惠券的点击率和使用率，查看用户操作录屏）
  - H3 [hypothesis]：首页放置首单红包入口+优惠前置可能提升转化（支撑事实：高文颖提到到店业务线类似策略有效；contradicting_evidence：卫帅楠担忧红包入口影响老用户信息流体验；置信度：low；验证方式：设计A/B测试首页红包入口）
- `open_questions`：
  - 首单转化率下降是否与选餐流程改版直接相关？（关联H1，验证：对比改版前后各步骤的转化率趋势，priority: high，blocking: false）
  - 下单耗时数据3→5分钟是否准确？（关联H1，验证：查下单流程埋点数据，priority: high，blocking: false）
  - 首页红包入口是否会影响老用户信息流体验？（关联H3，验证：小流量灰度测试老用户核心指标，priority: medium）
- `opportunities`：首页优惠前置可能降低首单流失（可行性：medium，不写成"应该加首单红包弹窗"）
- `analysis_confidence`：medium（有数据支持但下单耗时数据置信度低）
- `fact_hypothesis_separation`：true
- 不得出现编造的数字
- H3 的 contradicting_evidence 必须提及卫帅楠的担忧
- 不得输出功能方案

## Case 2：数据异常型场景 — 外卖满减活动核销率下降

**前置条件**：Skill 02 的 Case 2 已执行并通过确认。

**输入**：

```
项目名称：外卖满减活动核销率异常分析
项目目标：定位近期外卖满减活动核销率下降的原因并给出优化建议

已确认材料总结（摘要）：
- 核心事实：整体核销率从15%降至9%（高置信度）；APP弹窗渠道从20%降至8%（高置信度）；Push/短信渠道持平（高置信度）；满减门槛从满20改为满30（高置信度）；弹窗样式08月1日上线（中置信度，高文颖说确认但张思琪不确定）；用户评价提到"券太少"和"门槛太高"
- 冲突点：高文颖确认弹窗改了 vs 张思琪不确定改没改
- 观点：高文颖猜测弹窗样式导致；卫帅楠认为满减门槛也可能是因素；卫帅楠认为不排除其他原因

当前指令：根据材料总结分析核销率下降的核心原因
```

**期望输出要点**：

- `user_profiles`：外卖满减券用户（有外卖消费需求的C端用户，对满减门槛和券面额敏感，价格敏感型占比较高）
- `scenarios`：
  - 弹窗领券并下单场景（触发：APP首页弹窗展示满减券 → 期望：领券后下单时使用优惠 → 实际：可能未注意到弹窗，或领券后因门槛过高未使用）
- `pain_points`：
  - 弹窗渠道领券后核销率骤降（影响：高，频率：frequent）
  - 用户认为满减门槛过高不划算（影响：medium，频率：occasional）
  - 用户感觉券量不足不够用（影响：medium）
  - 有用户提到考虑竞品（影响：high）
- `known_facts`：至少5条引用
- `cause_hypotheses`：
  - H1 [judgment]：弹窗样式变更导致用户注意力下降，领券后未使用增加（支撑事实：弹窗渠道降幅最大、弹窗08/01上线时间吻合；置信度：medium；contradicting_evidence：弹窗样式变更未经张思琪确认；验证方式：拉取弹窗样式变更前后的点击率和领券后核销率对比）
  - H2 [judgment]：满减门槛提高降低了用户实际使用意愿（支撑事实：门槛从满20改为满30、用户评价"门槛太高"；置信度：high；验证方式：对比不同门槛下券的核销率，分析用户客单价分布）
  - H3 [hypothesis]：弹窗样式变更和门槛提高存在叠加效应（支撑事实：两者时间接近且同时影响核销率；置信度：low；验证方式：分别控制变量分析，拉取只改门槛或只改弹窗的子样本）
  - H4 [judgment]：Push和短信渠道未受影响说明问题集中在弹窗渠道（支撑事实：Push/短信持平；置信度：high；验证方式：确认其他渠道发券量和核销数据）
- `open_questions`：
  - 弹窗样式是否确实在08/01变更？（关联H1，验证：找前端开发确认变更记录，priority: high，blocking: false）
  - A/B测试数据是否可以找回？（关联H1，验证：联系当时测试负责人或查实验平台，priority: high）
  - 是否存在其他同时期变更的影响？（关联H3，验证：拉取08月前后所有外卖产品变更记录，priority: medium）
- `opportunities`：恢复弹窗样式或优化弹窗领券入口位置可能提升弹窗渠道核销率（可行性：medium）
- `analysis_confidence`：medium（部分关键事实如弹窗变更时间未完全确认）
- 冲突点（高文颖 vs 张思琪关于弹窗是否变更）必须体现在 H1 的 contradicting_evidence 中
- 不得编造核销率的具体分拆数字
